## 9. OPERATOR APPROVAL RULE

`[CONFIRMED_SOURCE]` (Safe Plan §4 Step 5 part E + Public Reveal Board §9 + runner-spec approval token convention):

A proposal exits `PROPOSAL_ONLY` only when the operator writes, verbatim:

```text
OPERATOR_APPROVED = YES — SCOPE = <specific clause being approved>
```

`[OUTLINE_ONLY]` rules:
- **Per-clause approval.** Operator approves clauses, not whole proposals in one stroke.
- **No batch approval.** A proposal with multiple clauses needs one `OPERATOR_APPROVED` line per clause.
- **No automated approval.** Tooling/Claude/Codex/GPT cannot self-approve at this gate.
- **No implicit approval.** Silence does not equal approval. Time passing does not equal approval.
- **Scope is mandatory.** Approval without a `SCOPE = ...` clause identifier is treated as missing.

Example (illustrative; not a real proposal):

```text
OPERATOR_APPROVED = YES — SCOPE = clause-3.2 "interior atmosphere description for safehouse"
```

vs. the rejected forms:

```text
OPERATOR_APPROVED = YES                              ← missing SCOPE; rejected
LGTM                                                  ← not the required wording; rejected
"go ahead"                                            ← not the required wording; rejected
operator silence for 7 days                           ← not approval; rejected
```

`[OUTLINE_ONLY]` rules:
