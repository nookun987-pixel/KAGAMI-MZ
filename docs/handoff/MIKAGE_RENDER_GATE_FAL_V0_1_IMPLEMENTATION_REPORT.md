## 6. WIRING NOTES

### 6.1 Path resolution

The tool walks up from the brief path searching for `docs/handoff/00_LATEST_CODEX_HANDOFF.md` as the repo-root marker. This makes it safe to invoke from any cwd, with relative or absolute brief paths. Fallback: `brief_path.parents[3]` (matches the `docs/automation/render_briefs/<brief>.json` layout).

### 6.2 Run-folder allocation

`attempt_NNN` auto-increments to the first unused 3-digit number, starting at 001 and bounded at 999. No overwrites. Each run lives in its own folder.

### 6.3 Gate cascade order

```text
if --dry-run                                  -> DRY_RUN_PASS_NO_API_CALL
elif operator_approval_token is null/false    -> RENDER_BLOCKED_OPERATOR_APPROVAL_REQUIRED
elif model_id == "CHUA_XAC_NHAN"              -> FAL_MODEL_ID_CHUA_XAC_NHAN
elif neither FAL_KEY nor FAL_API_KEY in env   -> FAL_API_KEY_MISSING
else:
    call FAL
    on failure                                -> FAL_API_REQUEST_FAILED
    on success + image downloaded             -> RENDER_OUTPUT_CREATED_VERIFY_NOT_STARTED
```

`--dry-run` deliberately wins over the safety gates so operators can always inspect what the tool would send to FAL without satisfying any unlock.

### 6.4 Source brief immutability is enforced by behavior + observed by audit

The tool never opens the brief in write mode. As an additional belt-and-braces measure, sha256 is taken before and after every run; the report carries both hashes and an `source_brief_unchanged` boolean. If a future bug or environmental contamination ever modifies the brief, the discrepancy lands in the report immediately.
