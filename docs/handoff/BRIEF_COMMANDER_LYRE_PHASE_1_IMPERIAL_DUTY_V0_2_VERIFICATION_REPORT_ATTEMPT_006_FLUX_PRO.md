## 5. ROOT-CAUSE READ (model-fitness diagnostic)

The PATH_F model swap was specifically designed to isolate model fitness. The result is informative:

**Three failure modes are MODEL-INDEPENDENT across the flux family:**
1. **POSE (hands behind back)** — both models default to hands-at-sides; prompt-only approach insufficient
2. **SHIELD (forearm disc emitter)** — both models drop wrist-scale attachment details
3. **MONOWIRE (hip hilt)** — both models drop hip-scale weapon details

These three persist regardless of flux variant. Mitigation requires non-prompt approaches: ControlNet pose conditioning, IP-Adapter for hardware attachments, LoRA fine-tuning, or switching to a different model family entirely (SD3.5, SDXL+ControlNet, Midjourney).

**flux-pro vs flux/dev trade-off matrix:**

| Dimension | flux/dev | flux-pro |
|---|---|---|
| Material discipline | Vinyl/plastic-leaning | **Proper hard ceramic ✓** |
| Color palette discipline | Amber embellishment habit | **Clean Empire cyan ✓** |
| Environment / architecture | **Empire monolith respected ✓** | Defaults to studio product framing |
| Mecha clutter | Less indicator iconography | **Adds cyan status indicators (knee lights, chest icons)** |
| Pose discipline | Hands at sides | Hands at sides |
| Wrist/hip detail attachment | Dropped | Dropped |
| Silhouette gendering | Slightly more female-leaning | More burly/industrial ✓ |

flux-pro is a **better hard-surface portrait renderer**; flux/dev is a **better scene/environment renderer**. Neither solves the model-independent POSE / SHIELD / MONOWIRE failures.

**Combined trade-off:** PATH_F resolved 2 V0.2/flux-dev fails (F4 amber, F1 material) at the cost of introducing 2 new fails (F3 knee lights, ERA_TAG lost backdrop). Net check count is similar (5 vs 6 fails), but the FAILURE PROFILE shifted from "embellishment + material" to "iconography + framing."
