> Small deterministic local CLI that reads a Mikage prompt_pack/v0.1 JSON sidecar, validates approval status, converts the long brief prompt into a compact render prompt, calls FAL **only when allowed**, saves outputs into a structured run folder, and writes attempt reports. Infrastructure only. Does NOT render, asset-lock, or mark PASS without explicit operator gates.

---

## 1. WHAT THIS TOOL IS

A hard-gated CLI render gate for FAL. The tool's job is to make it *impossible* to accidentally call a paid render API or produce a render claim from inside the repo without operator-explicit unlocks.

The tool is single-file Python 3 (stdlib only — no third-party deps). It is safe to run in dry-run mode at any time.

---

## 3. HARD GATES (order of precedence)

In every run, the tool computes a single status. The first gate that triggers (top-down in this list) wins:

| # | Trigger | Status | Effect |
|---|---|---|---|
| 1 | CLI flag `--dry-run` is set | `DRY_RUN_PASS_NO_API_CALL` | Write compact prompt + negative + `fal_request.json` + reports. Do NOT call FAL. |
| 2 | `project_metadata.operator_approval_token` is null in the brief | `RENDER_BLOCKED_OPERATOR_APPROVAL_REQUIRED` | Same as dry-run: no API call, reports written. |
| 3 | `config.model_id == "CHUA_XAC_NHAN"` | `FAL_MODEL_ID_CHUA_XAC_NHAN` | Same as above. V0.1 ships with this value as a deliberate safety stop. |
| 4 | Neither `FAL_KEY` nor `FAL_API_KEY` env var is set | `FAL_API_KEY_MISSING` | Same as above. |
| 5 | All gates open → API called → call fails | `FAL_API_REQUEST_FAILED` | `fal_response.json` written (if any body received). No output image. |
| 6 | All gates open → API called → call succeeds → image downloaded | `RENDER_OUTPUT_CREATED_VERIFY_NOT_STARTED` | `output.png` saved in run folder. **Verification status remains NOT_STARTED.** |

If any of those gates triggers, the tool exits cleanly with code 0 after writing the attempt report. Code 2 is reserved for usage errors (e.g. brief path not found) that happen before any gate logic runs.

## 4. USAGE

### 4.1 Dry-run (safe)

```bash
python tools/render_gate/mikage_render_gate_fal.py \
    --brief docs/automation/render_briefs/BRIEF_COMMANDER_LYRE_PHASE_1_IMPERIAL_DUTY_V0_1.json \
    --dry-run
```

This is the recommended first invocation. It will:
- Read the brief
- Allocate `docs/automation/render_briefs/runs/<BRIEF_ID>/attempt_001/`
- Write `prompt_compact.txt`, `negative_compact.txt`, `fal_request.json`, `render_attempt_report.json`, `render_attempt_report.md`
- Print a JSON summary to stdout
- Exit 0 with status `DRY_RUN_PASS_NO_API_CALL`

### 4.2 Default (no flags) — still gated

```bash
python tools/render_gate/mikage_render_gate_fal.py \
    --brief docs/automation/render_briefs/BRIEF_COMMANDER_LYRE_PHASE_1_IMPERIAL_DUTY_V0_1.json
```

For the V0.1-shipped state (`model_id = "CHUA_XAC_NHAN"`, no operator token on the brief), this is effectively a slightly-different dry-run path: same artifacts, but the status reflects WHICH gate stopped the run.

### 4.3 Real render (only when operator has unlocked all gates)

```bash
export FAL_KEY="..."                                 # operator's FAL key
# operator edits brief JSON:
#     "operator_approval_token": "<token-string>"
# operator edits tools/render_gate/mikage_render_gate_config.json:
#     "model_id": "fal-ai/flux/dev"   (or whatever model is approved)
python tools/render_gate/mikage_render_gate_fal.py \
    --brief docs/automation/render_briefs/BRIEF_COMMANDER_LYRE_PHASE_1_IMPERIAL_DUTY_V0_1.json
```

After a successful run, the image lands at:
```
docs/automation/render_briefs/runs/<BRIEF_ID>/attempt_NNN/output.png
```

The render is **NOT** copied to the brief's `output_target.output_path`. Promotion is operator-only and only after a Cowork-drafted verification report.

## 7. COMPACT PROMPT (V0.1)

V0.1 ships a single compact prompt deliberately scoped to **Commander Lyre Phase 1 Imperial Duty**. It does **not** auto-generate from the sidecar's `primary_prompt` — that's intentional. The compact prompt is the operator-vetted short form. The long sidecar prompt remains the canonical reference.

If the tool is run against a brief with a different `brief_id`, it still ships the V0.1 compact prompt and writes a note in the attempt report. V0.2 should add per-brief-id routing.

The compact prompt and compact negative are stored verbatim in `prompt_compact.txt` and `negative_compact.txt` per run.

Operator unlock procedure (also documented inline in the config):

1. Operator sets `project_metadata.operator_approval_token` in the brief JSON (separate edit; this tool never edits the brief).
2. Operator edits the config and replaces `model_id: "CHUA_XAC_NHAN"` with a concrete FAL model id.
3. Operator exports `FAL_KEY` (or `FAL_API_KEY`) in their shell.
4. Operator runs the tool without `--dry-run`.
5. Cowork drafts a verification report against the brief's `verification_checklist` (separate task — never automatic).

## 9. SAFETY INVARIANTS

The tool is built so the following are true regardless of CLI flags or config edits short of patching the source:

- Never modifies the source brief JSON. (SHA256 is taken before and after and recorded in the report.)
- Never writes anywhere outside `docs/automation/render_briefs/runs/<BRIEF_ID>/attempt_NNN/`.
- Never marks `verify_status` anything other than `"NOT_STARTED"`.
- Never marks `anchor_established`, `canon_lock`, or `asset_lock` anything other than `"NO"`.
- Never copies the rendered image to the brief's `output_target.output_path`. Promotion is operator-only.
- Never reads or writes Canon V1 or Canon V2 files.

## 10. WHAT TO DO AFTER A SUCCESSFUL RENDER

Operator's next steps (do NOT do these automatically):

1. Inspect `docs/automation/render_briefs/runs/<BRIEF_ID>/attempt_NNN/output.png` visually.
2. If it looks on-spec, ask Cowork to draft a verification report against the brief's `verification_checklist`. Cowork applies every check and reports PASS / FAIL / PASS_WITH_NOTE per check — Cowork does NOT mark the overall render PASS.
3. Operator reviews Cowork's findings and decides:
   - APPROVE → operator (not Cowork) promotes the image to the brief's `output_target.output_path` and updates the relevant character record. This is when `anchor_lyre_001` (or equivalent) becomes the canonical visual.
   - REVISE → Cowork drafts brief V0.2 with revision notes; V0.1 preserved as audit trail.
   - REJECT → output stays in the run folder; new attempt iterated next session.

## 11. TROUBLESHOOTING

| Symptom | Likely cause | What to check |
|---|---|---|
| `RENDER_BLOCKED_OPERATOR_APPROVAL_REQUIRED` | Brief has `operator_approval_token: null` | Operator must set the token in the brief JSON (separate edit). |
| `FAL_MODEL_ID_CHUA_XAC_NHAN` | Config still ships the V0.1 safety stop | Operator must edit the config and pick a concrete model. |
| `FAL_API_KEY_MISSING` | Neither env var set | `export FAL_KEY=...` or `export FAL_API_KEY=...` |
| `FAL_API_REQUEST_FAILED` | API rejected the request OR network error OR response shape unrecognized | Inspect `fal_response.json` in the attempt folder. |
| Source brief sha256 changed during run | This MUST NOT happen | File a bug; the tool is supposed to be read-only on the brief. |
| `output.png` saved but image quality is bad | Expected occasionally; this tool does not judge quality | Operator inspects + Cowork drafts verification report. |
