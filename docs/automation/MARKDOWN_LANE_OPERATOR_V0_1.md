## 1. PURPOSE

Define a repeatable, guardrailed, gated "auto-lite" framework for the **markdown / repo lane** only.

The framework's job:

- Take ONE input file.
- Produce ONE markdown output file.
- Run the verify gate.
- Write a report.
- Update a pointer.
- **STOP** at a hard gate and wait for human (operator) approval before any commit / push.

The framework's job is **not**:

- to render images,
- to batch process files,
- to mass-generate anything,
- to approve canon,
- to asset-lock anything,
- to call anything production-ready,
- to commit or push without explicit operator approval.

This file is the framework spec. The runner template is in `MARKDOWN_LANE_RUNNER_TEMPLATE_V0_1.md`. The build report for this scaffold pass is in `MARKDOWN_LANE_BUILD_REPORT_V0_1.md`.

## 3. FIXED STEP SEQUENCE

Every run, every time, in this order. No reorder. No skip. No add.

```text
1.  READ INPUT
    - Open exactly ONE input file (markdown or other text).
    - Record the input path in the run's report.
    - If input does not exist or is empty: FAIL → STOP.

2.  PRODUCE ONE MARKDOWN OUTPUT
    - Write exactly ONE markdown output file.
    - Path must match active_task.yaml output_folder_allowed / output_files_allowed.
    - No second file. No images. No binary. No subfolder. No .mp4.

3.  RUN VERIFY GATE
    - Execute: python .mikage/tools/verify_output.py
    - Capture stdout.
    - PASS = stdout literal "PASS"
    - Any other output, exception, or non-zero exit = FAIL.

4.  WRITE REPORT
    - Write a per-run report markdown file.
    - Required fields (verbatim names):
        RESULT
        FILES_READ
        FILES_CREATED
        VERIFY_STATUS
        ISSUES_FOUND
        NEXT_SAFE_TASK
    - VERIFY_STATUS must be either PASS (with the literal "PASS" stdout copied in)
      or FAIL / CHUA_XAC_NHAN (with the failure message captured).

5.  UPDATE POINTER
    - Update ONE operator-named pointer file with the new output path + report path.
    - Do not silently update docs/handoff/00_LATEST_CODEX_HANDOFF.md unless the operator names it as the pointer.
    - If no pointer file is named: skip this step, mark POINTER_UPDATED = NO in the report.

GATE: HARD STOP FOR HUMAN APPROVAL
    - The run halts here.
    - The runner does NOT commit. The runner does NOT push.
    - The runner waits for an explicit operator directive of the form:
        OPERATOR_APPROVED = YES — TARGET = <output file path> — REASON = <one line>
    - Without this directive, no commit / push is permitted.

(operator-approved only)
6.  COMMIT
    - One commit only.
    - Commit message must cite: the input file, the output file, the report file, the pointer file (if updated),
      and the OPERATOR_APPROVED token verbatim.

7.  PUSH
    - One push only.
    - Push only the branch named in the active task.
    - No force push.
    - Record the commit hash + push result in a follow-up commit report.
```

## 4. THE VERIFY GATE

The gate is `python .mikage/tools/verify_output.py`. Per its source contract:

| Requirement | Meaning |
|---|---|
| Reads `.mikage/tasks/active_task.yaml` | The active task must exist and be a YAML mapping. |
| Requires `output_folder_allowed` | Must be repo-relative; must exist; must be a directory; must resolve inside the repo. |
| Requires `output_files_allowed` | Non-empty list of allowed filenames (relative paths). |
| Walks `output_folder_allowed` recursively | Every file under it must be in `output_files_allowed`; no unexpected directories. |
| For `task_type = CONTACT_SHEET_ONLY` | Only `contact_sheet.png` + `contact_sheet_review_report.md`; **any `.mp4` is FAIL**. |
| PASS contract | Prints literal `PASS` and exits 0. |
| FAIL contract | Prints `FAIL: <message>` and exits non-zero. |

**PASS evidence rule:** The runner may only mark a step PASS if it captured the literal stdout string `PASS` from `verify_output.py`. Any other value = FAIL.

If the gate prints FAIL, the runner:

- Marks `VERIFY_STATUS = FAIL`.
- Marks `RESULT = FAIL`.
- Captures the FAIL message verbatim in `ISSUES_FOUND`.
- **Stops.** Does not retry. Does not auto-correct. Does not commit. Does not push.

If the gate output is missing, ambiguous, or the runner cannot capture it:

- Marks `VERIFY_STATUS = CHUA_XAC_NHAN`.
- Marks `RESULT = CHUA_XAC_NHAN`.
- **Stops.** Does not assume PASS.
